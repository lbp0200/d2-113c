## 1. 三条判断线：什么该修，什么不该修

原版的"不合理"分三类，待遇完全不同。这是本设计的核心：

| 类型 | 例子 | 处理 |
|---|---|---|
| **可学且可解** | 知道去噩梦雇 A2 就有力量光环；知道崔凡克刷符文；知道堆降抗 | **不修**。这是玩法深度，修了等于把游戏变薄 |
| **不可解** | 抗性 160 需要 300 点降抗（原版凑不到）；A3 铁狼贵 40% 却少 37% HP | **必须修**。玩家再懂也没用，这是"错" |
| **只是不透明** | 游戏不告诉你地狱档 A2 光环更差 | **不修**（见下） |

第三条要特别说明：原版大量"不合理"其实是**信息不透明**——你有对策，只是没人告诉你。
理想修法是 UI/提示，但那需要 Dll 补丁（P4）。
**用数值去补偿信息缺失是错药**：它会让老玩家觉得游戏变简单，又没解决新玩家的困惑。
所以这一类一律归入"不做"。

**判据三问**（每条改动都要过）：
1. 玩家懂了之后能自己解决吗？能 → 不修。
2. 修了之后玩家需要重新学一个职业/一套流程吗？需要 → 降级或不做。
3. 能不能用现有工具**量化前后差异**？不能 → 先别改。

## 2. 核心诊断

### 诊断一：元素免疫的错不在"免疫"，在"抗性超过可破上限"

免疫本身是设计（113~137 个怪物地狱免疫，物理只有 3%、魔法 1%，说明暴雪做过分配）。
真正的问题是**抗性数值超过了玩家能达到的降抗上限**：

抗性 R 要降到 100 以下，需要 `-res ≥ R-100`；对免疫怪降抗只按 **1/5** 生效，
所以实际需要 `5×(R-100)` 点降抗。

按"能凑到 100 点降抗"（信念/无限 + 降抗诅咒 + 装备）估算，可破上限是**抗性 120**：

| | 免疫(≥100) | **无解(>120)** | 最高抗性 |
|---|---:|---:|---:|
| 火 | 113 | 16 | 145 |
| 冰 | 137 | **102** | 1000 |
| 电 | 105 | 3 | 145 |
| 毒 | 131 | 27 | 1000 |
| 物理 | 20 | 0 | 100 |
| 魔法 | 11 | 1 | 145 |
| **合计** | — | **149** | — |

**149 个怪物对单元素 build 是无解**，其中冰系 102 个。
而且 `Act 3 - Mephisto 3` 与 `Act 5 - Ice Cave 2` 是 **100% 全怪无解**的区域
——前者是主线必经。

> 修正一处此前说过头的话：崔凡克不是 100% 无解。`cantor3` 冰抗 160 确实无解，
> 但 `vampire2` 冰抗 120 恰好卡在阈值上（可破）。准确说法是**崔凡克两种怪里有一种打不了**。

### 诊断二：协同硬编码，等于关闭了"混元素"这条出路

`Skills.txt`(256 列) 与 `SkillDesc.txt`(114 列) **没有任何 syn/ergy 列**——1.13c 的协同加成
硬编码在 Dll 里。这意味着：

- 正常设计里，玩家遇到免疫会"投资第二元素"，而协同机制**惩罚**分散投资；
- 我们改不了协同，所以更不能容忍"无解抗性"——两条路都堵着。

**这条约束反过来加固了诊断一：封顶抗性不是"削弱难度"，是补上原版缺失的出口。**

### 诊断三：佣兵是"定价错"，不是"强度错"

85 级地狱横向对比（A2 为基准）：

| 佣兵 | HP | 相对 | 物理伤害 | 相对 | 雇价 | 相对 |
|---|---:|---:|---:|---:|---:|---:|
| A1 罗格 | 1319 | −19% | 131-133 | +2% | 14000 | −7% |
| A2 沙漠 | 1630 | — | 124-131 | — | 15000 | — |
| **A3 铁狼** | 1025 | **−37%** | 53-60 | **−54%** | 21000 | **+40%** |
| **A5 野蛮人** | 1430 | −12% | 97-101 | −23% | 32000 | **+113%** |

而且 A3 的真实输出其实不低（火球 23 级 436-489、冰爆 25 级 687-718），
它的问题是 **HP 最低 + 每级成长最低（+27 vs A2 的 +40）+ 没有光环**。

A2 的优势不在面板，在**光环**：噩梦档给 力量 / 神圣冰冻 / 荆棘，
地狱档却只给 祈祷 / 反抗 / 祝福瞄准。**原版在惩罚"在地狱雇佣兵"。**

### 诊断四：一批技能是死内容，但"修死技能"是最高风险的改动

同职业内差距能到 20 倍（亚马逊：Power Strike 伤害/法力 62.9 vs Magic Arrow 3.0）。
但结合诊断二——协同改不了——想救一个废技能只能加本体伤害，那它就变成"又一个火球"，
职业特性反而消失。

**结论：不做技能平衡。** 除了"明显笔误级"的个别数值，其余一律不碰。

## 3. 改动清单

### A 档 · 已做（证据充分、风险最低、可量化验证）

#### A1 · 地狱元素抗性封顶 100 ✅ 已实现

- **补丁**：`patches/balance.py` —— 把 `ResFi(H)/ResLi(H)/ResCo(H)/ResPo(H)` 里
  `>100 且 <1000` 的值封顶到 100，共 **332 处**。
- **为什么排除 `≥1000`**：那 17 个（16 毒 + 1 冰）是**设计上的绝对免疫**，不是"不合理"。
- **为什么这不是"降难度"**：免疫怪数量一个都没减少（还是打不动），
  只是让任何 `-res` 都能生效。
- **量化验证**（`python3 -m tools.p1_immunity --overlay mod`）：

  | | 免疫(≥100，按元素累计) | 无解(>120，按元素累计) | 100% 死角区域 |
  |---|---:|---:|---:|
  | vanilla | 517 | **149** | **2**（Mephisto 3、Ice Cave 2） |
  | 封顶后 | **517** | **18** | **0** |

  → **难度完全不变（517 = 517，有免疫的怪仍然是 482 个），"无解"减少 88%（149→18），死角清零。**
  剩下的 18 个全是 `≥1000` 的设计性免疫 + 1 个魔法 145。

### B 档 · 待做（需要游戏可测后再实施）

> 以下三条都**必须等 VM 装好、能实际进游戏后再做**：数值改动的手感无法离线验证。

#### B1 · A3 铁狼：HP 上调 + 雇价下调

- **证据**：HP −37% 而雇价 +40%，且每级成长最低。
- **修法**：`hireling.txt` 中 `Eastern Sorceror` 全难度档 `HP` 与 `HP/Lvl` 各 ×1.35
  → 85 级 HP 1025 → 约 1384（A2 的 85%）。`Gold` 21000 → 12000。
- **不做什么**：不动它的技能等级。它打得不弱，弱在活得短。
- **风险**：低（不碰 `itemstatcost`、不碰存档位、玩家不用重新学职业）。
- **验收**：进地狱实际带一次，确认它不会变成"打不死的肉盾"（那是另一种失败）。

#### B2 · A5 野蛮人：只改定价

- **证据**：雇价 +113%，面板 −12%/−23%，且两个技能都是纯单体控制、对队伍零增益。
- **修法**：`Gold` 32000 → 15000。**不改技能**。
- **为什么不改技能**：给它光环就是"第二个 A2"，等于抹掉职业差异。
- **验收**：确认价格调整后它仍然是"没人选"，那就接受——这属于"设计上就不该选"。

#### B3 · 检查"无解抗性"是否还会挡住必经主线

- A1 之后已无 100% 死角区域，但还需确认：**主线必经的 boss/精英**里
  没有单点 `>120` 的抗性（例如某个必须打的暗金怪）。
- 这项属于**验证**而非改动，等能跑游戏时用 `--overlay` 报告 + 实走一遍主线确认。

### C 档 · 明确不做（负面清单）

> 这份清单比 A/B 档更重要——它防止项目滑向"大改"。

| # | 不做 | 理由 |
|---|---|---|
| C1 | 技能协同调整 | **硬约束**：硬编码在 Dll，txt 没有列 |
| C2 | 技能重做 / 加新技能 | 违反"不改技能树结构"；且协同改不了，救废技能只会造出第二个火球 |
| C3 | 天梯符文之语解锁 | 不在 txt 里（`server` 列全空），走 PlugY 的 `ActiveLadderRunewords` |
| C4 | 地狱档 A2 光环改回噩梦档 | 这是"可学且可解"的隐藏知识，修了等于抹掉一层玩法 |
| C5 | 那 17 个 `≥1000` 抗性 | 设计性绝对免疫，不是错 |
| C6 | 大背包 / 大箱子 / 大盒子 | 属于 PlugY 范畴，且会让 `inventory.txt` 与 Dll 失配 |
| C7 | 崔凡克掉落表 / 符文经济 | 符文掉率是 1.13 刻意调过的；单机最优解是 LK 超级箱子，不是崔凡克 |
| C8 | 修改 `itemstatcost.txt` | 会毁存档（Save Bits / stat ID） |
| C9 | 近战 vs 法系整体曲线 | 需要改 `weapons.txt` 全表 + 攻击帧，属于大改，且无法离线验证 |

## 4. 实施顺序与验证闭环

```
1. [已完成] A1 封顶抗性          → 已量化验证（149→18 无解，2→0 死角）
2. [下一步] B1/B2 佣兵定价与 HP  → 需 VM 可测
3. [验证]  B3 主线必经点复查      → 需 VM 可测
4. [顺带]  装 PlugY 解决 C3/回城/仓库等摩擦（零 txt 风险）
```

**每次改动的固定动作**（这是纪律，不是建议）：

```bash
python3 -m tools.build --dry-run            # 看清楚要改哪些行
python3 -m tools.build                      # 产出 mod/ + changelog
python3 -m tools.p1_immunity --overlay mod  # 量化"世界变成什么样"
python3 -m tools.validate                   # 结构校验（表头/主键/脏值）
git commit -m "<一句话说清改了什么、为什么>"
```

**为什么要有 `--overlay`**：报告工具默认只看 `vanilla/`，看不到自己的改动效果。
加了 overlay 之后，"改动 → 量化"才闭环——A1 的 149→18 就是这么算出来的，
而不是靠手感声称"应该会好一点"。

## 5. 一句话总结

四份报告收敛出的结论只有一条：

> **原版的难度大部分来自"可学的东西"和"信息不透明"，这两类不该修；
> 真正该修的只有一小撮"玩家再懂也做不到"的地方——主要是 149 个无解怪物，
> 以及 A3/A5 的错价。**

这也解释了为什么"轻度修补"的空间比想象的小：**能修的地方不多，但修对了收益很大。**
