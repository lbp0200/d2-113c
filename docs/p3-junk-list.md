## 四、重做方法（我们的框架）

一件装备要"有身份"，必须能回答 **E1**：**谁、在什么阶段、为了哪一项属性穿它。**

三条落地手段（都不需要改 Big5 字符串表）：

| 手段 | 说明 | 例子（你提的三个方向） |
|---|---|---|
| **换底材** | `uniqueitems.txt` 的 `code` 列可以改 —— 同一件暗金换成别的底材，名字不变 | `Razortine` 从矛 → **斧**（高耐久、可破免） |
| **换属性组** | `prop1..12` 整组替换，保留名字 | `Hellplague` → **近战 + 火焰技能联动**（`extra-fire` / `firemastery`） |
| **加新机制** | 触发技能、光环、`pierce-*`、`oskill` | `Plague Bearer` → **毒系终局手套**（`pierce-pois` + `extra-pois`） |

**验收方式固定**：改完在 [`p2-areas.md`](p2-areas.md) 的框架下算出"环境系数"，确认它真的把某个场景从"不可用"变成"可用"，而不是加了一堆看起来不错的数字。

## 五、为什么不能只靠指标（教训）

我试过三种自动识别"垃圾装备"的方法，**全部有明显误判**：

| 方法 | 结果 | 典型误判 |
|---|---|---|
| 严格支配（每项都不差） | 0 件 | 太严格 |
| 强属性条数 | 69 件 | 把 **Arkaine's Valor**（req 85、+2 全技能）判成被 req 16 的 `Twitchthroe` 超越 |
| 同槽位百分位 | 同类误判 | 同上 |

根因：D2 装备的价值在**数值幅度、属性组合、触发效果**，不在"属性条数"。
所以**用户/社区名单 + 逐件人工判断**是目前唯一可靠的入口 —— 这份文件就是那个入口。
